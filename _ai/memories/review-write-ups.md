In review and audit write-ups:

- Tag any finding or question that needs Kyle's answer `[Kyle?]`, next to
  the other evidence tags (see [[evidence-over-inference]]). Never a bare
  `[Kyle]`.
- When Kyle asks for the findings restated, write them fresh, as if for a
  first-time reader: number the findings afresh, and drop old finding
  numbers, test IDs and back-references such as "as above" or "was #3".

**Why:** Kyle asked for both while reviewing a security write-up
(2026-11-20): "Instead of `[Kyle]` denoting when I need to answer
something, say `[Kyle?]`. And there's no need to state the old finding
numbers. I want you to restate fresh like someone is reading it for the
first time."

**How to apply:** use `[Kyle?]` from the first draft of any review; on a
restatement request, rewrite the whole report instead of patching the
previous one with cross-references.
